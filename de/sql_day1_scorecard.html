Q8 — date functions
★★★☆☆
5/10
Good thinking — you knew to use LAG and two CTEs. But the first CTE uses SUM as a window function over rows rather than GROUP BY month, which gives a running total per row, not one total per month. The LAG in CTE 2 also has no proper date column to order by.
WITH monthly AS ( SELECT DATE_TRUNC('month', sale_date) AS month, SUM(amount) AS revenue FROM sales WHERE EXTRACT(YEAR FROM sale_date) = 2023 GROUP BY 1 ) SELECT month, revenue, LAG(revenue) OVER (ORDER BY month) AS prev_revenue, ROUND( (revenue - LAG(revenue) OVER (ORDER BY month)) / LAG(revenue) OVER (ORDER BY month) * 100, 2 ) AS pct_growth FROM monthly ORDER BY month;
Q9 — deduplication
★★☆☆☆
3/10
Wrong approach: DELETE * is invalid syntax. Also, your subquery only selects duplicate keys but doesn't identify which specific rows to delete — this would wipe all matching rows, not keep one. The correct strategy uses ROW_NUMBER to tag duplicates, then deletes where rank > 1.
-- Standard approach (works in PostgreSQL, SQL Server): WITH ranked AS ( SELECT order_id, ROW_NUMBER() OVER ( PARTITION BY customer_id, product_id, order_date ORDER BY order_id ) AS rn FROM orders ) DELETE FROM orders WHERE order_id IN ( SELECT order_id FROM ranked WHERE rn > 1 );
Q10 — consecutive days streak
★★★☆☆
5/10
You got the right idea — the classic "date minus row_number = constant group" pattern is exactly correct. But: (1) Missing closing parenthesis in the subquery. (2) Typo: logn_date. (3) GROUP BY needs grps too. (4) The SELECT for start date should be MIN(login_date).
SELECT user_id, MIN(login_date) AS streak_start FROM ( SELECT user_id, login_date, (login_date - CAST(ROW_NUMBER() OVER ( PARTITION BY user_id ORDER BY login_date ) AS INT)) AS grp FROM user_logins ) t GROUP BY user_id, grp HAVING COUNT(*) >= 3 ORDER BY user_id, streak_start;
